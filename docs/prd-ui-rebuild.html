01 Context

A research questionnaire for medical students in cohorts 2023–2025, measuring nomophobia (NMP-Q, 20 items) alongside depression and anxiety symptoms (DASS-21 subscales, 7 items each). Respondents get an instantly scored result and educational content. Data lands in Cloudflare D1, optional screentime screenshots land in R2, and the researcher exports everything as XLSX.

Users: medical students, 18–25, mostly on mobile, filling this once, unpaid, for roughly fifteen minutes of their time.

Why redesign. The current UI works but reads as flat and long. Twenty NMP-Q items sit stacked on a single scrolling page with bare numeric radio labels (1 2 3 4 5 6 7) at 10px — high cognitive load and a real drop-off risk on a phone. There is no progress indicator, no save-and-resume, and a single generic error line at the bottom of each step.

The thing that shapes every design decision here

Two of the three instruments screen for depression and anxiety. The redesign has to feel calm and non-alarming on those screens. Expressive motion belongs on the landing and result screens — not on "Saya merasa hidup ini tidak berarti."

02 Goals & non-goals

Goals

  1. Reduce perceived length — visible progress, chunked questions, a sense of momentum.
  2. Raise completion rate — the primary success metric.
  3. Modernize the visuals while keeping the warm rose/peach identity. It was designed for this study; it should not be thrown away.
  4. Add a considered motion layer — expressive on landing and results, restrained on clinical screens.
  5. Improve mobile ergonomics — larger tap targets, labeled Likert anchors, no horizontal cramming.
  6. Stay honest — this is a screening tool, not a diagnosis, and the disclaimer stays prominent.

Non-goals

  • Changing questionnaire item text, scale wording, item order, or scoring thresholds.
  • Changing the backend API contract.
  • Accounts, login, or individual-level analytics tracking.
  • Dark mode — the palette is a warm light gradient by design.
  • Multi-language support.

03 Design system prompt

Paste this into Stitch before anything else. Everything in section 4 assumes it has already been set.

Stitch prompt · paste first 
Design a warm, calm, editorial-feeling web app for a psychology research questionnaire aimed at university students in Indonesia. Mobile-first, also responsive to tablet and desktop. The mood is gentle, human, and reassuring — not clinical, not corporate, not "startup SaaS".

COLOR PALETTE (use exactly these):
- Page background: a soft diagonal gradient at 135°, from #f8c9d3 (rose pink) at 0%, through #fbdcc4 (peach) at 55%, to #fdecd3 (warm cream) at 100%.
- Primary text: #3a2b30 (deep warm brown)
- Primary deep accent: #7a3350 (deep plum-rose) — buttons, active states, heading accents
- Primary light accent: #c9587e (rose) — used only as the light end of gradients
- Muted border / inactive stroke: #b06a82 at 40–100% opacity
- Card surface: white at 35% opacity with a 6px backdrop blur, corner radius 24px, no hard border
- Primary button: pill shape (fully rounded), 90° linear gradient #c9587e to #7a3350, white text, soft shadow 0 6px 16px rgba(122,51,80,0.35)
- Secondary button: pill shape, transparent background, 2px border #7a3350, text #7a3350
- Result severity badges — circular, 56px, white bold numeral inside. Level 1 green #7cc576, level 2 yellow #e8c34a, level 3 orange #f0a15d, level 4 red #e2604f, level 5 dark red #8a2c40

TYPOGRAPHY:
- Headings: Playfair Display, weights 600/700/800. Large, generous line-height, sentence case (often all-lowercase for playful lines).
- Body: Lora, weights 400/500/600. Comfortable reading size, relaxed line-height of 1.6 or more.
- Never use a geometric sans for headings. The serif pairing is the identity.

SHAPE AND TEXTURE:
- Pill-shaped buttons and inputs, fully rounded, never square.
- Frosted glass cards floating on the gradient.
- Soft, hand-drawn illustration style for spot images, with a paper-like feel. Illustrations sit directly on the gradient with no white box behind them.
- Floating soft white cloud shapes as ambient background decoration on the landing screen.
- Generous whitespace. Content column max-width about 640px on mobile and tablet, up to about 1100px on desktop, always centered.

COMPONENT CONVENTIONS:
- Radio option: 24px circle, 2px border #b06a82, filled with a gradient dot when selected, with a springy pop scale-in on select.
- Text input: full-width pill, 1px border #b06a82, translucent white fill, border darkens to #7a3350 on focus.
- File upload: full-width dashed-border drop zone, 2px dashed #b06a82, 16px radius, upload arrow icon, translucent white fill.
- Disclaimer and note blocks: frosted card, smaller text, centered.

ACCESSIBILITY:
- Minimum tap target 44x44px.
- Body text never smaller than 14px, helper text never smaller than 12px.
- All interactive elements need a visible focus ring in #7a3350.
- Text contrast must pass WCAG AA against the light gradient. Use #3a2b30 or #7a3350, never light grey.

Keep all Indonesian text exactly as written — do not translate, do not paraphrase.

05 React Bits motion map

Stitch cannot generate this section

Stitch outputs static HTML/CSS or a Figma file. React Bits is a copy-paste React library — you paste component source into the project rather than installing a package. This section is the implementation brief for whoever builds the React app on top of Stitch's output. Verify exact component names and props against reactbits.dev; the library moves.

Motion principles for this product

  1. Motion budget scales inversely with clinical seriousness. Landing and results: expressive. Biodata and NMP-Q: functional feedback only. DASS screens: near-zero decorative motion.
  2. Every animation is skippable. prefers-reduced-motion: reduce disables all decorative motion, leaving only opacity fades under 150ms.
  3. Nothing loops in peripheral vision while someone reads a question. Ambient background animation is landing and result only.
  4. No motion gates input. Entrance animations never delay interactivity.

06 Technical plan

The stack change this requires

React Bits is React-only. The app today is Alpine.js served as static files. This rebuild means introducing React.

  1. Add Vite + React, building into dist/, and point [assets] directory in wrangler.toml at it.
  2. Leave the Worker at src/index.js completely unchanged — it already falls through to env.ASSETS.fetch(request) for anything that isn't an API route.
  3. Keep Tailwind v4. React Bits components are Tailwind-friendly. Preserve the custom CSS in src/css/app.css (buttons, radio pop, badges) as the base layer.
  4. src/data.js stays the single source of truth and the React app imports it directly. This finally kills the manual cp src/data.js public/data.js sync step documented in the README.
  5. Pull in motion, gsap, and ogl only as individual components require them.
Migration order

The Alpine state machine in public/app.js is small and clean — step, form, validateCurrentStep(), submit(), carousel index. Porting it to React state is a few hours, not a rewrite. Port the logic verbatim first, verify parity against the current build, then restyle. Doing both at once is how the DASS offset below gets broken without anyone noticing.

Performance budget

Respondents are on Indonesian mobile networks. These are hard limits:

MetricBudget
Initial JS, gzipped≤ 180 KB
LCP on 4G, mid-tier Android≤ 2.5 s
Total page weight, landing≤ 600 KB

This budget is what decides whether WebGL backgrounds ship at all. three.js alone blows it; ogl is around 30 KB. Prefer OGL-based React Bits backgrounds, load them with React.lazy, and only on landing and result. If the budget still can't be met, keep the existing pure-CSS cloud animation — it costs zero JS and already looks good.

Accessibility requirements

  • Full keyboard navigation. Likert rows are radio groups navigable with arrow keys, one tab stop per question.
  • Correct semantics: <fieldset> + <legend> per question, role="radiogroup", aria-required.
  • prefers-reduced-motion: reduce disables all decorative motion. Hard requirement, not a nice-to-have.
  • Progress changes announced via aria-live="polite".
  • On validation failure, focus moves to the first unanswered question rather than only showing a bottom error line.

08 Hard constraints

Non-negotiable. Violating any of these invalidates the research data.

Instrument integrity

  • NMP-Q: exactly 20 items, in the exact order in src/data.js, response values 1–7.
  • DASS-21 Depression: exactly 7 items, exact order, submitted values 1–4.
  • DASS-21 Anxiety: exactly 7 items, exact order, submitted values 1–4.
  • Item wording is verbatim. No shortening, no rephrasing, no friendlier rewrites, no emoji.
  • Scale labels are verbatim.
Read this one twice · the DASS display/value offset

The DASS scales are displayed to the user as 0, 1, 2, 3 but submitted to the server as 1, 2, 3, 4. In the current code this is x-text="entry.value - 1" on display while entry.value is what gets sent (public/index.html:312), and the Worker validates 1 ≤ v ≤ 4 (src/index.js:63).

Any reimplementation must preserve this offset exactly. Getting it wrong silently shifts every DASS score by 7 points and pushes respondents into the wrong severity category — with no error, no warning, and no way to tell from the exported spreadsheet that it happened.
